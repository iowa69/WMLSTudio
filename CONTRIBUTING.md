# Contributing to WMLST

Thanks for being here. WMLST is maintained by **IOWA-Tech — Giovanni Lorenzin**, and
patches, bug reports and test cases are all welcome.

Before anything else, please read the one rule that shapes everything below.

---

## The one rule

> **A change that alters a typing result is a breaking change, no matter how small the
> diff is.**

WMLST exists to reproduce `mlst` 2.35.0 byte for byte. Someone's published ST calls
depend on that. A "harmless tidy-up" that reorders a dictionary, rounds instead of
truncating, or strips a trailing tab is not harmless — it is a silent data corruption
that will surface in a paper two years from now.

So: `docs/ARCHITECTURE.md` is the specification, and it is authoritative. If your change
disagrees with it, either the change is wrong or the spec needs amending **in the same
pull request**, with the reasoning written down.

## Getting set up

```bash
git clone https://github.com/iowa69/WMLST.git
cd WMLST
python -m pip install -e ".[dev]"

# NCBI BLAST+ (2.9 or newer)
sudo apt install ncbi-blast+          # or: conda install -c bioconda blast
                                      # or on Windows: wmlst --bootstrap-blast

wmlst --make-blast-db                 # builds db/blast, ~12 s
python -m pytest -q
```

> **Do not set `core.autocrlf=true`.** `.gitattributes` protects the allele files, but
> the safest setting on Windows is `git config core.autocrlf input`. A rewritten line
> ending changes an allele's MD5, which changes every `--novel` identifier it produces.

The repository intentionally contains a 116 MB allele database in `db/pubmlst/`. It is
not a mistake, it compresses to about 5.8 MB of git objects, and it must never be
gitignored or moved to LFS. `db/blast/` is derived and *is* ignored.

## Before you open a pull request

```bash
python scripts/check_stdlib_only.py wmlst     # zero third-party runtime imports
python scripts/check_headers.py               # SPDX header on every source file
python packaging/make_icon.py --verify -o packaging/wmlst.ico
ruff check wmlst scripts packaging tests
python -m pytest -q
```

All five must pass. CI runs exactly these.

## House rules

**Python 3.9 is the floor.** No `X | Y` annotations, no `match`, no `zip(strict=)`, no
`dict | dict`. `ruff` is configured to catch the common ones but not all of them.

**No third-party runtime dependencies. None.** This is a licensing constraint, not a
preference: WMLST is `GPL-2.0-only`, and a GPLv2 work cannot link an Apache-2.0 library
because the patent-termination clause is a further restriction GPLv2 §6 forbids.
`tkinterdnd2` (MIT), behind a `try/except ImportError`, is the single sanctioned
exception. Anything else needs a licence review before the code review.

**Respect the module layering** (`docs/ARCHITECTURE.md` §2.1). The import graph is
acyclic and enforced by `tests/test_layering.py`:

- `subprocess` appears in `blastbin.py` and nowhere else.
- `gui.py` never imports `subprocess`, and no worker closure imports `tkinter`.
- `report.py` imports the engine's dataclasses, never its functions. It does no
  biology; every number it prints is already final.

**Every ported regex carries `re.ASCII`.** Perl's `\d` and `\w` are ASCII-only by
default and Python's are not. A Unicode digit in a sequence id is the difference
between a parsed allele and a dropped one.

**Every `.py` file starts with the SPDX header.** `python scripts/check_headers.py --fix`
inserts it. Files that are direct translations of upstream Perl must also name the
upstream file and line range they came from — that is a GPL attribution obligation, not
bookkeeping.

**Comment the surprises, not the obvious.** The codebase reproduces several upstream
bugs deliberately. Those need a comment saying *why*, so the next contributor does not
"fix" them. Ordinary code needs no narration.

**Never hard-code a vendor string.** Import from `wmlst/branding.py`.

## Tests

| If you changed... | Run at least |
| :-- | :-- |
| scoring or the algorithm | `pytest tests/test_scoring.py tests/test_golden.py` |
| BLAST parsing | `pytest tests/test_engine_parse.py -m needs_blast` |
| any output format | `pytest -m golden` — this is the byte-identity gate |
| the CLI | `pytest tests/test_cli_bats_parity.py tests/test_cli_help.py` |
| the GUI | `pytest tests/test_gui_headless.py tests/test_layering.py` |
| packaging, CI, licensing | `pytest tests/test_packaging.py` |

Useful markers: `-m "not slow"`, `-m needs_blast`, `-m golden`, `-m windows`,
`-m network` (needs `WMLST_TEST_NETWORK=1`).

**The golden corpus in `tests/golden/` is generated by running the real Perl `mlst`,
and is never hand-edited.** If a golden test fails, the overwhelmingly likely cause is
that your change altered the output. Regenerating the golden file to make the test pass
defeats the entire point of the project; `tests/golden/SHA256SUMS` and `PROVENANCE.txt`
exist to make doing it by accident impossible.

## Reporting a bug

The most useful bug report contains the input file. If you can share it, please do —
even a reduced one. Otherwise, include:

- `wmlst --version` and `wmlst --check` output,
- the exact command line,
- what you expected and what you got,
- the database version from `db/VERSION.txt`,
- for a mismatch against upstream, the `mlst` version and its output.

Security issues: please open a private security advisory on GitHub rather than a public
issue.
