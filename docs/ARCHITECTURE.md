## 0. THE EXACT-COMPATIBILITY CONTRACT (read this first)

> **WMLST output for the bundled fixtures MUST be byte-identical to `tseemann/mlst` 2.35.0 for
> TSV, CSV and JSON.** This is the acceptance criterion for the whole project. Every other goal —
> the GUI, the HTML report, the installer, the updater — is subordinate to it.

Concretely, for every file in `/home/iowa/Desktop/wmlst/tests/data/` and against the bundled
`db/pubmlst` snapshot `2025-12-29`:

| Surface | Contract |
| :-- | :-- |
| default TSV (stdout) | byte-identical to `mlst --quiet --skipcheck --nopath FILE` |
| `--full` TSV | byte-identical |
| `--full --csv` | byte-identical |
| `--legacy --scheme X` | byte-identical |
| `--list`, `--longlist`, `--info` | byte-identical |
| `--json` | structurally identical after JSON deserialisation; key ORDER is fixed by WMLST (upstream's is a randomised Perl hash) — see D2 |
| `--novel` FASTA | identical as a set of `{id: sequence}` records; record ORDER is fixed by WMLST — see D7 |
| exit codes | identical (§14) |
| `wrn()` / `err()` lines on stderr | identical except the `ERRPR:`→`ERROR:` typo fix — see D3 |

**Line terminator is LF (`\n`) on every platform, including Windows**, for TSV, CSV, JSON and the
novel FASTA. Every output stream MUST be opened with `newline="\n"` (or `newline=""` plus explicit
`"\n"` writes). A single `\r` anywhere in a compat output is a release blocker.

**Encoding is UTF-8 without BOM.** `--json` additionally uses `ensure_ascii=True`, matching Perl's
`to_json(..., {ascii=>1})`.

The golden files in `tests/golden/` are generated by the **real Perl `mlst`** (script
`scripts/make_golden.sh`) and are the definition of correct. They MUST NOT ever be regenerated from
WMLST. `tests/golden/SHA256SUMS` is verified by the test suite so that "fixing" a failing test by
regenerating the golden is impossible without a loud, deliberate act.

### 0.1 The five things that silently break parity

1. **Regexes without `re.ASCII`.** Python's `\w`, `\d`, `\S`, `\D` are Unicode-aware by default;
   Perl's are byte semantics here. Every ported regex MUST pass `re.ASCII`.
2. **Reassociating the score arithmetic.** `int(s * 90 / n)` ≠ `int(s * (90 / n))` in IEEE-754 for
   31 known input shapes, and the exact `float` accumulation order matters for 79 of 986 enumerated
   `(n, n~, n?, n-)` tuples. See §5.9 steps 42-43 and the pinned reference table.
3. **Coercing allele numbers to `int`.** They are strings and may be decimal (`2.002`).
4. **CRLF.** A `\r` on the last BLAST output column silently turns `sstrand` into `"plus\r"`, the
   `== "minus"` test never fires, and `--novel` emits un-reverse-complemented sequences with wrong
   MD5s. Read BLAST output with universal newlines AND `rstrip("\r\n")`.
5. **Perl falsiness.** `$x || '-'` treats `undef`, `""` **and the string `"0"`** as absent. Eleven
   shipped schemes contain literal `0` allele values in their profile tables.

## 3. SHARED DATA STRUCTURES — defined ONCE, here

All of these live in **`wmlst/engine.py`** and are imported from there by every other module.
All are `@dataclass(frozen=True)` unless stated. All use `slots=True` where Python ≥ 3.10 is
available (guard with a conditional decorator; the floor is 3.9).

**Typing rules that apply to every structure below:**

* Every allele number, ST and allele code is a **`str`**, never an `int`. `"2.002"`, `"007"`,
  `"-"`, `"0"`, `"~10"`, `"3?"`, `"1,2"` are all valid values and MUST round-trip unmodified.
* `score` is an **`int`** everywhere after `engine` computes it. It is never a float in any
  structure, is never formatted with a decimal point, and is never re-derived downstream.
* Collections that cross a module boundary are **`tuple`**, never `list` (frozen dataclasses,
  hashability, and accidental-mutation safety).
* Nothing in these structures is `None` "because we didn't know" — a missing value is `"-"` for
  codes, `None` only where the field is explicitly declared optional.

### 3.1 `Hit` — one surviving BLAST HSP

```python
@dataclass(frozen=True)
class Hit:
    """One line of `blastn -outfmt '6 sseqid slen length nident qseqid qstart qend qseq sstrand'`
    that matched the sseqid regex AND passed the mincov gate.

    Field order below mirrors the BLAST column order EXACTLY. The single highest-risk
    transcription error in this port is swapping `slen` (column 2) with `length` (column 3);
    `slen` is the ALLELE length, `length` is the ALIGNMENT length.
    """
    sseqid:  str    # col 1, verbatim, e.g. "saureus.arcC_1"
    scheme:  str    # regex group 1  -- everything before the FIRST '.'
    locus:   str    # regex group 2  -- may contain '_' (e.g. "glmU_1", "16S_rRNA")
    allele:  str    # regex group 3  -- STRING; may be "12" or "2.002". NEVER int().
    slen:    int    # col 2  -- Perl $hlen: length of the reference allele
    length:  int    # col 3  -- Perl $alen: length of the alignment
    nident:  int    # col 4
    qseqid:  str    # col 5  -- contig id, UNTRUSTED user data
    qstart:  int    # col 6  -- 1-based inclusive, as BLAST reports
    qend:    int    # col 7  -- 1-based inclusive
    qseq:    str    # col 8  -- aligned query sequence, returned UPPERCASE by BLAST
    sstrand: str    # col 9  -- exactly "plus" or "minus"
    # ---- derived once, in engine.parse_blast(); never recomputed downstream ----
    pct_identity: float   # 100.0 * nident / length
    pct_coverage: float   # 100.0 * nident / slen   <-- the quantity --mincov is tested against
    call_kind:    str     # "exact" | "novel" | "partial"   (see 3.1.1)
    index:        int     # 1-based order of appearance in mlst.bls; ties are resolved by this
```

**3.1.1 `call_kind` derivation (engine-owned, `bin/mlst:342,357`):**

```
exact    if slen == length and nident == slen      # full length AND 100% identity
novel    if slen == length and nident <  slen      # full length, >= minid, not identical  -> "~N"
partial  if length != slen                          # partial coverage                      -> "N?"
```
With `-ungapped`, `length <= slen` always; `length > slen` is impossible.

**3.1.2 `used`** is deliberately NOT a field on `Hit`. Which hits contributed to a call is
expressed by `AlleleCall.best` / `AlleleCall.hits`; duplicating it invites the two to disagree.

### 3.2 `AlleleCall` — one locus of the winning scheme

```python
@dataclass(frozen=True)
class AlleleCall:
    """One locus of the reported scheme, in PROFILE-HEADER gene order (Scheme.genes)."""
    locus:  str            # gene name exactly as it appears in <scheme>.txt's header
    code:   str            # THE authoritative string. Exactly what appears inside gene(...) in the
                           # TSV, inside the signature, and as the JSON allele value.
                           # One of: "16" | "~16" | "16?" | "-" | "0" | "1,2" | "2.002" | ...
    symbol: str            # classification of `code`, one of:
                           # "exact" | "novel" | "partial" | "missing" | "null" | "multiple"
    best:   "Hit | None"   # the hit that SET the code; None when symbol in {"missing","null"}
    hits:   tuple[Hit, ...]  # every surviving hit for this locus, ordered by Hit.index.
                             # Includes `best`. Empty when the locus was never hit.
```

**3.2.1 `symbol` derivation — from `code` alone, in this exact order:**

```python
def classify(code: str) -> str:
    if code == "-":                                   return "missing"
    if code == "0":                                   return "null"
    if "," in code:                                   return "multiple"
    if code.startswith("~"):                          return "novel"
    if code.endswith("?"):                            return "partial"
    return "exact"
```
Note `"0"` is tested before the numeric case: a `0` code is the `/-`→`/0` rewrite (§5.9 step 41), not an
allele named zero. No shipped scheme has an allele `0`.

**3.2.2 `display()`** is NOT a method. Rendering `f"{locus}({code})"` belongs to `report.py`.

### 3.3 `SchemeScore` — one candidate scheme for one sample

```python
@dataclass(frozen=True)
class SchemeScore:
    """One row of the candidate table built at bin/mlst:368-395, including the sentinel."""
    scheme:    str    # scheme name, or "-" for the sentinel
    st:        str    # sequence type as a STRING, or "-"
    signature: str    # "/"-joined codes AFTER the /- -> /0 rewrite. For the sentinel:
                      #   "/".join(["-"] * allele_cnt)
    score:     int    # final integer score, post +10-if-ST
    num_loci:  int    # Scheme.num_genes (= len(genes)); 0 for the sentinel
    n_exact:   int
    n_novel:   int    # count of "~" in the PRE-rewrite signature
    n_partial: int    # count of "?"
    n_missing: int    # count of "-" in the POST-rewrite signature (what scoring used)
    n_null:    int    # count of "0" produced by the rewrite
    excluded:  bool   # dropped by --exclude at bin/mlst:338
    below_minscore: bool   # score < --minscore, dropped at bin/mlst:395
```
The sentinel is `SchemeScore(scheme=forced_scheme or "-", st="-", signature="-/"*…, score=0,
num_loci=0, n_*=0, excluded=False, below_minscore=False)`.

### 3.5 `SampleResult` — everything about one input file

```python
@dataclass(frozen=True)
class SampleResult:
    # ---- identity -------------------------------------------------------------
    path:    str        # the argv string, verbatim, UNTRUSTED. JSON "filename".
    label:   str        # $LABEL: --label, else basename if --nopath, else path. UNTRUSTED.
                        # This is the FILE column and the JSON "id".
    # ---- the call -------------------------------------------------------------
    scheme:    str      # winning scheme name, or "-"
    st:        str      # sequence type STRING, or "-"
    signature: str      # post-rewrite, "/"-joined
    score:     int      # 0..100
    status:    str      # PERFECT|NONE|NOVEL|MIXED|MISSING|BAD|OK  (status_column, §5.15)
    alleles:   tuple[AlleleCall, ...]    # EMPTY tuple when scheme == "-"
    # ---- evidence -------------------------------------------------------------
    candidates: tuple[SchemeScore, ...]  # every scored scheme incl. the winner and the sentinel,
                                         # already sorted: -score, then scheme name. Index 0 is
                                         # the winner.
    novel:      tuple[NovelAllele, ...]  # only populated when RunConfig.novel_path is set
    warnings:   tuple[str, ...]          # rendered warning text: the bin/mlst:344 duplicate-exact
                                         # msg() lines and the bin/mlst:405 tie wrn() lines
    # ---- provenance / telemetry (report + GUI only; never affects the call) -----
    n_contigs:  int
    total_bp:   int
    hits_seen:  int     # lines parsed by the sseqid regex (Perl $res_count)
    hits_kept:  int     # lines that survived mincov + scheme + exclude
    elapsed_s:  float
    failed:     bool    # True when this file errored; all call fields are then "-" / 0 / empty
    error:      "WmlstError | None"
    error_text: str     # one-line human message; "" when failed is False
```

`failed=True` rows exist so that batch mode can continue past a bad file (upstream dies). They are
NEVER written to the compat TSV/CSV/JSON outputs — upstream produces no row for a file that kills
it, so neither do we. They appear in the GUI, the HTML report, and the WMLST-only evidence TSV.

### 3.6 `RunConfig` — the complete, frozen input to a run

### 4.3 `wmlst/any2fasta.py` — owner B

**Parser contracts that affect results:**

* **FASTA** (any2fasta:202-225): drop lines matching `^\s*$`; emit every other line **verbatim**.
  Deflines keep their description. Line wrapping, case and non-ACGT characters are untouched.
  `messy.fa` has a single 282,005-character sequence line and MUST survive unchanged — stream
  line-by-line, never `readlines()`.
* **GenBank** (any2fasta:280-323): `//` flushes `">"+acc+"\n"+"".join(dna)`; `ORIGIN` sets
  `in_seq`; inside the sequence, `line[10:]` then remove ALL whitespace; outside,
  `^LOCUS\s+(\S+)` sets `acc`. A record with no trailing `//` is silently dropped. A coordinate
  ≥ 10 digits would eat a base — that is an upstream bug; reproduce it, log at `--debug`.
* **EMBL** (any2fasta:327-371): `^SQ\s` sets `in_seq`; inside, remove `[ \t]` **first**, then strip
  a trailing `\d+$`; outside, `^ID[ \t]+([^;\t ]+)` sets `acc`.
* **GFF3** (any2fasta:244-255): discard every line until one starts with `>`, then push it back and
  run the FASTA parser. No embedded FASTA ⇒ 0 sequences ⇒ `EmptyInputError`.
* **FASTQ** (any2fasta:229-240): strict 4-line stride; a trailing incomplete record is dropped.
* `empty.fa` (content `>empty_seq\n`) produces **1** record and **no** any2fasta error; the
  `Sequence contains no data` message comes from **BLAST** (exit 3), not from here (§8.6).

**`-db` MUST be the bare basename with `cwd` AND `BLASTDB` both set to the index directory.**
`blastn` splits the `-db` value on whitespace *inside* BLAST, after `CommandLineToArgvW`, so an
argv list does not rescue a path containing a space; it fails with
`BLAST Database error: No alias or index file found for nucleotide database [C:/Program]` and exit
code 2. `-query` and `-out` are single-value options and *do* tolerate spaces; they stay absolute.
Verified: the bare-name + `cwd` + `BLASTDB` form produces byte-identical output to the space-free
control.

**Every flag is load-bearing. Do not add, remove or reorder any of them:**

| Flag | Why it cannot change |
| :-- | :-- |
| *(no `-task`)* | the default task is **megablast**; `-task blastn` changes seeding and HSP boundaries ⇒ different `length`/`nident` ⇒ different calls |
| `-ungapped` | guarantees `length == aligned span`, no `-` in `qseq`, and `length <= slen` always. The whole `alen == hlen` / `alen < hlen` dichotomy depends on it |
| `-dust no` | DUST masking would lose/truncate HSPs and can return lowercase `qseq` |
| `-word_size 32` | speed, and a deliberate sensitivity ceiling: SNPs spaced < 32 bp apart can lose an allele entirely |
| `-max_target_seqs 100000` | the default 500 would silently truncate a locus with thousands of alleles; the value also feeds BLAST's internal ranking heuristics |
| `-perc_identity <minid>` | this IS the `--minid` gate; it is identity over the ALIGNMENT, not over the allele |
| `-evalue 1E-20` | the string must be exactly `1E-20` |
| `-num_threads` | verified byte-identical output for 1/2/4/8/16 threads and for `-mt_mode 1`/`2`. Never pass `-mt_mode`. |
| `-lcase_masking` | **MUST NOT be passed.** GenBank `ORIGIN` output is lowercase and would be fully masked. Verified: a 100 %-lowercase query yields 23,675 hits with full-length identity without it. |

`blastn` exits 0 even with zero hits. Exit codes are catalogued in §8.6.

### 5.6 Parsing (steps 28–33) — `bin/mlst:320-332`

28. Open `mlst.bls` with `encoding="utf-8", errors="replace", newline=None` (universal newlines)
    and `rstrip("\r\n")` every line anyway. **Never** open it with `newline=""`.
29. Match each line against `HIT_RE` (§4.6). Lines that do not match are **silently skipped** and
    do not increment the counter. Exactly three loci in the shipped DB never parse:
    `halobacteria.EF-2_*` (43 alleles), `halobacteria.rpoB'_*` (44) and `mhominis_3.p120'_*` (21) —
    108 alleles lost. **Reproduce this; do not fix it** (see §5.19).
30. Increment `hits_seen` (Perl `$res_count`, incremented *before* the debug line, so it counts
    parsed lines including ones later dropped).
31. Emit at `--debug`:
    `[{n}] {qid}:{qstart}-{qend}({sstrand}) | {sch} {gene} {num} | id={nident}/{alen} | cov={alen}/{hlen} | seq={qseq}`
32. **The mincov gate** (`bin/mlst:332`): keep the hit iff
    ```python
    nident / hlen >= mincov / 100        # hlen is slen, BLAST column 2
    ```
    The numerator is `nident`, **not** `length`. Both sides are IEEE-754 doubles; compute it
    exactly this way and **never cross-multiply into integers**, or boundary cases flip. Because
    `-perc_identity` already enforced `nident/length >= minid/100`, `--mincov` is a combined
    coverage×identity gate.
33. Then, in this order:
    * if `cfg.scheme` is set and `sch != cfg.scheme`: drop (dbg `Skipping {sch}.{gene}.{num} allele
      as user specified --scheme {scheme}`);
    * if `sch in cfg.exclude`: drop (dbg `Excluding {sch}.{gene}.{num} due to --exclude option`).
      (A no-op under `--scheme`, since the exclude set was cleared at step 16.)
    Surviving hits increment `hits_kept` and are appended to the hit list with `index` = their
    1-based order of appearance.

**Regex notes that are easy to get wrong:**
* `re.ASCII` is mandatory (§0.1).
* There is **no `$` anchor**; trailing extra columns are tolerated.
* Greedy backtracking is load-bearing: `leptospira.glmU_1_12` yields `gene="glmU_1"`, `num="12"`.
* `(\w+)\.` means the scheme is everything before the **first** dot; `a.b.c_1` never parses.
* `[_-]` — the locus/allele separator may be `_` **or** `-`.
* `(\d+(?:\.\d+)?)` — the allele may contain one decimal point (`ngstar.penA_2.002`). Keep it a
  **string** for its entire life.

### 5.7 Building calls (steps 34–37) — `bin/mlst:342-364`

Maintain `res[scheme][gene] -> code` and `nov[scheme][gene] -> str` (either the `'N'` sentinel or a
captured sequence). Process hits in **BLAST output order**.

34. **Exact branch** — `slen == length and nident == slen`:
    ```python
    prior = res[sch].get(gene)
    if prior is not None and not re.search(r"[~?]", prior):
        msg(f"WARNING: found additional exact allele match {sch}.{gene}-{num}")
        res[sch][gene] = prior + "," + num
    else:
        msg(f"Found exact allele match {sch}.{gene}-{num}")
        res[sch][gene] = num
    nov[sch][gene] = "N"          # UNCONDITIONAL; overwrites any captured sequence
    ```
    Consequences to preserve exactly: a prior `~5` or `5?` is **overwritten** (no comma); a prior
    `3` becomes `3,N`; a prior `3,3` contains no `[~?]` so it appends again. The separator in the
    message is a **hyphen** (`{sch}.{gene}-{num}`) even though the DB uses `_`. Both messages are
    `msg()`, **not** `wrn()`, so `--quiet` hides them (`test.sh:111-116` therefore runs the
    un-quieted binary).
35. **Inexact branch** — everything else:
    ```python
    label = f"~{num}" if length == slen else f"{num}?"
    res[sch].setdefault(gene, label)                 # Perl ||= : FIRST WINS
    if cfg.novel_path and length == slen:
        seq = revcom(qseq) if sstrand == "minus" else qseq
        nov[sch].setdefault(gene, seq)               # FIRST WINS; 'N' is truthy so it is kept
    ```
    The `~` is a **prefix**, the `?` a **suffix**. Novel capture happens **only** for full-length
    (`~`) hits, **only** when `--novel` was given, and never overwrites an existing value.
36. Record, for every gene, the `Hit` that set the code as `AlleleCall.best`, and every surviving
    hit for that gene as `AlleleCall.hits` (ordered by `Hit.index`). For a `multiple` code, `best`
    is the hit that created the **first** component of the comma list.
37. `hits_kept` is now final.

### 5.8 The sentinel (step 38) — `bin/mlst:368`

38. Create the first candidate:
    ```python
    SchemeScore(scheme=(cfg.scheme or "-"), st="-",
                signature="/".join(["-"] * allele_cnt), score=0, ...)
    ```
    It is inserted **first** and is never filtered by `--minscore`, so it wins a 0–0 tie.

### 5.9 Scoring each candidate (steps 39–45) — `bin/mlst:370-395`

For each scheme name in **`sorted(res)`** (D1):

39. `sig_pre = scheme.signature_of(res[name])` — Perl falsiness, profile-header gene order.
40. `st = scheme.sequence_type(sig_pre)` — the lookup uses the **pre-rewrite** signature, because
    that is the form the genotype table stores.
41. **The `/-` → `/0` rewrite** (`bin/mlst:376`):
    ```python
    sig = sig_pre.replace("/-", "/0") if (st != "-" and "/-" in sig_pre) else sig_pre
    ```
    Both conditions are required. The pattern is `"/-"`, so a hyphen at **position 0** (first locus
    null) is **not** rewritten and keeps its full `-1.0` penalty and its `gene(-)` rendering.
    `str.replace` is non-overlapping left-to-right, identical to Perl's `s///g` here. The rewrite
    runs **before** scoring, so rewritten nulls cost nothing.
42. **The score** (`bin/mlst:382-392`) — transcribe this verbatim:
    ```python
    n = scheme.num_genes                 # len(genes); NOT the number of .tfa files
    s = float(n)
    s -= 0.3 * sig.count("~")
    s -= 0.5 * sig.count("?")
    s -= 1.0 * sig.count("-")
    score = int(s * 90 / n)              # Perl int(): TRUNCATES TOWARD ZERO
    if st != "-":
        score += 10
    ```
43. **Float mandate.** Use plain `float` and this exact operation order. `decimal.Decimal`,
    `fractions.Fraction`, integer scaling, `round()`, `math.floor()`, `//`, and any algebraic
    simplification are **forbidden**. Two independently verified facts:
    * `int(s*90/n)` ≠ `int(s*(90/n))` for **31** enumerated `(n, n~, n?, n-)` shapes, e.g.
      `n=7, ~=3, ?=1` → **71** (correct) vs 72 (wrong); `n=9, ~=1` → **86** vs 87.
    * Exact-rational arithmetic differs from IEEE-754 for **79 of 986** enumerated tuples with
      `n ∈ 3..10`, because e.g. `9 - 0.3 == 8.699999999999999` and `8.699999999999999*90/9 → 86`,
      not 87. The 986-row Perl-generated reference table lives at
      `/tmp/claude-1000/-home-iowa-Desktop-wmlst/12caaa71-cd44-4d35-9516-55648dcead69/scratchpad/sc.perl.txt`
      (`nlocii n~ n? n- score`); it MUST be copied into `tests/golden/scores.tsv` and asserted in
      full by `tests/test_scoring.py::test_all_986_tuples`.
    `//` is additionally wrong for negative intermediates: `int(-0.5*90/7) == -6` while
    `(-0.5*90/7)//1 == -7.0`.
44. Emit at `--debug`: `SCORE={score}\t{name}\t{st}\t{sig}\t({n} genes)`.
45. Keep the candidate iff `score >= cfg.minscore` (`>=`, on the **post-`+10`** value, compared as
    a float). Under `--scheme`, `minscore` is 0 so nothing is filtered.

**Reference scores for a 7-locus scheme** (regression anchors):
all exact → 90 (+ST = **100**); one `~` → 86 / 96; one `?` → 83 / 93; one `-` → 77 / 87;
two `-` → 64 / 74; three `-` → 51 / 61; four `-` → 38 / 48 (both dropped at the default minscore).
This is why `--minscore 50` admits up to three missing loci in a 7-locus scheme.

### 5.14 Choosing the winner (steps 46–48) — `bin/mlst:399-414`

46. `candidates.sort(key=lambda c: c.score, reverse=True)` — Python's sort is stable, so insertion
    order (sentinel first, then `sorted(res)`) breaks ties as the lexicographically smallest scheme
    name. Upstream sorts on score only, over a randomised Perl hash iteration, so its tie winner is
    a coin flip (verified: three consecutive runs over the same five keys produced three different
    orders). This is divergence **D1/C8**.
47. For every `i` in `1..len(candidates)-1` whose score equals `candidates[0].score`, emit
    ```
    WARNING: {c0.scheme}({c0.st})=={ci.scheme}({ci.st}) score={score} {path}
    ```
    via `wrn()` — **not suppressed by `--quiet`** (`Logger.pm:36-38`; `test.sh:187-190` relies on
    it). `{path}` is the raw argv path, **not** the label. `{score}` is formatted `str(int(score))`,
    never a float repr.
48. `winner = candidates[0]`. Under `--scheme`, assert `winner.scheme == cfg.scheme`.

### 5.15 Post-processing and status (steps 49–52) — `bin/mlst:167-220, 275-284`

49. **Prune `nov`** to the winning scheme only. If `winner.scheme == "-"`, discard everything for
    this label.
50. `codes = [] if winner.scheme == "-" else winner.signature.split("/")`. When the scheme is `-`
    the code list is deliberately empty even though the signature is `-/-/…/-`.
51. **Numeric duplicate sort** (`bin/mlst:177-184`), applied **in place** to each code so the
    result flows into the printed row, the `--full` ALLELES column and the JSON `alleles` map:
    ```python
    if "," in code and re.fullmatch(r"[\d.,]+", code, re.ASCII):
        code = ",".join(sorted(code.split(","), key=float))   # sorted() is stable
    ```
    Both guards are required, so `~5,6` and `5?,6` are left untouched. `float()` reproduces Perl
    numification for these strings. Wrap in `try/except ValueError` and leave the field unsorted on
    failure (unreachable with the shipped DB). Pinned by `test.sh:123-126`:
    `"10.001,2.002,2.001"` → `"2.001,2.002,10.001"`.
52. **`status_column(st, score, codes)`** — the order of the tests IS the specification
    (`bin/mlst:275-284`). The seven values are the complete vocabulary; no others exist.
    ```python
    if re.fullmatch(r"\d+", st, re.ASCII):                              return "PERFECT"
    if score <= 0:                                                      return "NONE"
    if not any(re.search(r"\D", c, re.ASCII) for c in codes):           return "NOVEL"
    if any("," in c for c in codes):                                    return "MIXED"
    if any("-" in c for c in codes):                                    return "MISSING"
    if score < 70:                                                      return "BAD"
    return "OK"
    ```
    Notes: `PERFECT` is decided from the **ST alone**, so a scheme can be `PERFECT` while carrying
    `0` (rewritten null) codes; a decimal ST such as `206.2` would not be `PERFECT`. `MISSING`
    tests whether a code *contains* `-`, not whether it equals `-`. The `NOVEL` branch with an
    empty `codes` list is unreachable, because `codes` is empty only when the scheme is `-`, in
    which case `score == 0` and `NONE` already returned.
    Pinned fixtures: `example.fna`→PERFECT, `mixed.fa.zip`→MIXED, `novel.fa`→NOVEL,
    `messy.fa`→MISSING, `none.fa`→NONE (`test.sh:131-150`).

### 5.17 Novel-allele assembly (run level) — `bin/mlst:230-250`

For each sample in argv order, then scheme, then gene in `scheme.genes` order (D7 — upstream
iterates three randomised Perl hashes):

* skip entries whose value is the `'N'` sentinel (literal string comparison; reproduce it even
  though a 1-base allele is impossible);
* `md5 = hashlib.md5(seq.encode("ascii")).hexdigest()` over the post-revcom, BLAST-cased sequence;
* `fasta_id = f"{scheme}.{locus}-{md5}"`;
* **deduplicate on `fasta_id` across all input files**; the first occurrence wins and carries its
  label into the description;
* `msg("Found", n, "novel alleles")`;
* write the file even when `n == 0` (an empty file is still created).

### 5.19 The three shipped-DB quirks, in full

**(a) `aphagocytophilum` — 8 "genes", 7 `.tfa` files.** Its profile header is
`ST pheS glyA fumC mdh sucA dnaN atpA clonal_complex MLST_cluster` (verified on disk).
`MLST_cluster` is not on `Scheme.pm:46`'s six-name exclusion list, so `genes` has **8** entries
ending in `MLST_cluster` — the only scheme in the DB where `len(genes) != count(*.tfa)`.
Consequences, all of which MUST be reproduced: the 8th signature field is always `-`; the genotype
signature's 8th field is the **clonal_complex** column value, so an ST is reachable only for the
93 of 206 rows whose `clonal_complex` is empty; the maximum achievable score is
`int(7*90/8) = 78`, `+10 = 88`, never 100; the status can still be `PERFECT`. A validator that
reconciles header genes against `.tfa` files would flag this and tempt a "fix" — do not write one.

**(b) The three unparseable loci.** `halobacteria.EF-2_N` fails because `(\w+)` can only take `EF`,
`[_-]` eats the `-`, `(\d+)` eats the `2`, and then a tab is required but `_1` follows, with no
backtrack path. `halobacteria.rpoB'_N` and `mhominis_3.p120'_N` fail because `'` is neither `\w`
nor `[_-]`. Downstream, verified: `halobacteria` has 5 genes of which 2 can never be called, 0 of
its profile rows have a null in those columns, so `sequence_type` can **never** return anything but
`-`; its maximum score is `int((5-2)*90/5) = 54`, which is above the default `--minscore`, so it is
always reported with `ST = -` and `STATUS = MISSING`. `mhominis_3` has 10 genes, 1 uncallable,
0 rows with a null there, maximum score `int(9*90/10) = 81`. The updater still downloads and stores
these loci verbatim, they are still counted in `_info.json`, and they still go into `mlst.fa`
(BLAST indexes an apostrophe in a defline fine, and `blastdbcmd -entry "halobacteria.rpoB'_1"`
returns the sequence). The loss happens **only** at the sseqid parse step. Emit a `--debug`-only
line when a row is dropped; never on stderr by default. `--repair-locus-ids` (C19) relaxes the
locus group to `([^\t]+?)` and is off by default.

**(c) Eleven schemes with literal `0` allele values in their profiles** — `brachyspira_2`,
`efaecium`, `hinfluenzae`, `leptospira_2`, `listeria_2`, `paeruginosa`, `sepidermidis`,
`shaemolyticus`, `spyogenes`, `suberis`, `szooepidemicus`. Perl falsiness turns them into `-` in
the genotype signature, which is what makes the `/-`→`/0` rewrite meaningful. Any Python
implementation that tests only `if value:` on a list index will get this right by accident and any
that tests `if value is not None:` will get it wrong.

## 7. THE UPDATE ALGORITHM (`updatedb.py`)

### 7.1 Endpoints (verified live)

| Purpose | URL shape |
| :-- | :-- |
| scheme document (the whole contract) | `{root}/db/{db}/schemes/{id}` — ~1.4 KB, carries `locus_count`, the unpaginated `loci` array in display order, `profiles_csv`, `last_updated` |
| profile table | `{root}/db/{db}/schemes/{id}/profiles_csv` — despite the name it is **TAB**-separated, LF, trailing `\n` |
| allele FASTA | `{root}/db/{db}/loci/{locus}/alleles_fasta` — headers `>{locus}_{allele}`, sequences **unwrapped** |

`/db/{db}/loci` is paginated and **MUST NOT be called** — the scheme document already names the
exact loci, saving ~70 wasted pages per database. There is **no bulk per-scheme allele download**;
one request per locus is unavoidable. `?return_all=1` is a no-op on `alleles_fasta` and must not be
sent.

Both hosts now cap anonymous clients at data submitted on or before 2024-12-31 and say so in a
`message` key. **The bundled DB is exactly that anonymous view** — verified byte-identical.
Authentication (OAuth 1.0a HMAC-SHA1, three-legged, per-database request/access/session tokens) is
an **opt-in advanced mode** that MUST be labelled in the GUI as *"produces a database that differs
from the reference `mlst` distribution"*, and it MUST set `_info.json`'s `authenticated` truthfully.

Neither API offers `ETag`, `Last-Modified`, `Content-Length` on HEAD, or gzip. Conditional GET is
impossible; resumability is journal-based.

### 7.2 Change detection — hash, never date

`last_updated` advances **daily** even though the anonymous payload is frozen (verified: `saureus`
scheme 1 reported `last_updated: 2026-09-10` while its `profiles_csv` was byte-identical to a March
download). A date-based updater therefore re-downloads all 162 schemes forever. And a row-count
check is not enough either: Pasteur's `listeria_2` has the same line count as the bundle but two
rows differ by a curation edit. **Only a content hash (§4.9 `content_sha256`) is a reliable
oracle.**

```
for each SchemeRef S in the manifest:
    meta = GET S.api                                   # 1 request, ~1.4 KB
    404 "has not been defined"  -> status retired-upstream; KEEP local data; continue
    meta.locus_count != S.nloci -> status quarantined;  KEEP local data; require confirmation
    if meta.last_updated has not advanced past wmlst_upstream_last_updated_at_verification:
        status up-to-date; continue                    # 0 payload bytes
    fetch profiles_csv and every alleles_fasta in meta.loci order
    if sha256 == wmlst_content_sha256:
        status date-moved-content-identical
        update _info.json's last_updated / download_date / verified_unchanged_at ONLY
        do NOT rewrite files and do NOT mark the scheme dirty
    else:
        status changed; validate (7.6); commit atomically (7.3); mark dirty
rebuild the BLAST index iff any scheme is dirty, or --force-blast, or index_is_stale()
```

A no-op check costs **162 requests / ~230 KB / ~15 s**. A full refresh is **1,432 requests /
~115 MB / 2–4 min** at 4-way concurrency (budget 10 min). Peak disk during an update is ~250 MB,
plus the index rebuild.

### 7.3 Atomicity, aliases, resumability

* Download into `db/pubmlst/.staging/<scheme>.<pid>/`; validate; then swap. On Windows
  `os.replace` cannot atomically replace a non-empty directory, so: rename live →
  `<scheme>.old.<pid>`, rename staging → `<scheme>`, delete `.old`. A crash between the two renames
  is repaired at next start from the journal.
* Any validation failure deletes the staging directory and leaves the live directory **untouched**.
* Alias pairs (`cdiphtheriae` / `diphtheria_3`) are fetched once and materialised twice.
* Journal: newline-delimited JSON at `db/.wmlst-update.jsonl`, `fsync`ed after each record, with
  `run_start`, `scheme_skip`, `scheme_fetch_begin`, `scheme_commit`, `scheme_error`, `run_end`
  events. `--resume` replays it, sweeps orphaned `.staging/` and `.old.*` directories, and
  continues. Because commits are per-scheme and atomic, an interrupted run always leaves a
  self-consistent tree.
* **Cancellation is honoured only between scheme commits**, so the GUI's "no restart required"
  promise holds.

### 7.4 Etiquette

Neither API documents a rate limit and neither throttled a 12-request burst, so the policy is
self-imposed: **4 in-flight requests per host** (PubMLST and Pasteur counted separately), 100 ms
per-worker delay, an identifiable `User-Agent` naming WMLST, IOWA-Tech, Giovanni Lorenzin and the
repository URL. Retry on 429/500/502/503/504 and on connect/read timeouts: 5 attempts, exponential
backoff 1/2/4/8/16 s with ±25 % jitter, honouring `Retry-After`. **Never retry 400/401/403/404.**
Circuit breaker: 10 consecutive failures against one host pauses it for 60 s; three pauses abort the
run with the journal intact. Connect timeout 15 s, read timeout 120 s (the largest single payload is
~1.1 MB). TLS verification stays **on**, with `certifi`-equivalent trust; never fall back to the
Windows store and never disable verification.

### 7.5 Discovery of new schemes — opt-in, default OFF

`GET {root}/db` on both hosts, then `/db/{db}/schemes` for each, keeping only schemes whose
`description` matches `(?i)\bMLST\b` **and** whose `locus_count` is in `[2, 15]` (the bundled range
is 3–10). Explicitly reject `cgMLST`, `rMLST`, `wgMLST`, `Core \d+`, `TCS-\d+`. Propose a directory
name from the `_N` rule, collision-checked, and require operator confirmation. The GUI MUST warn
that adding a scheme absent from tseemann's distribution **changes typing results**, because a new
scheme competes in the auto-detect scoring, and therefore breaks the §0 contract.

### 7.6 Validation gates — all must pass before a commit

**Per `.tfa`:** HTTP 200; `Content-Type` starts with `text/plain`; the first byte is `>`; no line
begins with `<`; no blank lines; no `\r`; every header matches `^>{re.escape(locus)}_\S+$`; at least
one record; never a `{"message": …}` JSON body.

**Per `<scheme>.txt`:** HTTP 200; `text/plain`; the first line splits on `\t` into ≥ 2 fields with
`[0] == "ST"`; the header columns minus the six excluded names minus the scheme's `fields` names
equal the scheme document's `loci` set; every data row has the header's column count.
**Zero data rows is legal** (`mgenitalium`).

**Per scheme:** `.tfa` count == `meta.locus_count`; every locus in `meta.loci` has a file; total
staged bytes > 0 and, unless `--allow-shrink`, not less than 50 % of the live directory.

**Per locus name, before writing a file:**
`assert not set(locus) & set(':*?"<>|\\/')` — `:` would silently create an NTFS alternate data
stream. No shipped locus triggers this (the only non-alphanumerics across all 1,108 loci are `'`,
`-` and `_`), but a future scheme could. Record any locus failing `^\w+$` (ASCII) in
`wmlst_unparseable_loci` so the §5.19(b) problem stays visible as upstream grows.

**The legacy `downloadAlleles` web routes MUST NOT be used.** They now return an HTML login page
with HTTP 200 for valid and invalid loci alike, and the historical `grep -v 'not a locus'` filter
would not remove a byte of it.

## 8. WINDOWS RUNTIME CONTRACT

### 8.1 What the Perl does that cannot work on Windows

| Perl | Line | Failure |
| :-- | :-- | :-- |
| `system($cmd)` with `\Q…\E` quoting | 294-299 | a single command string goes through `cmd.exe`, which does not honour Perl's backslash escaping |
| `-outfmt '6 sseqid …'` | 314 | POSIX single quotes reach `blastn` literally |
| `any2fasta -q … > $FNA` | 307 | external Perl dependency plus shell redirection |
| `require_exe('blastn')` | Requirements.pm:52-70 | tests `-x "$dir/$exe"` and never appends `.exe`, so it always fails on Windows |
| one temp dir with two fixed filenames | 154, 304-305 | safe only because upstream is strictly serial |

### 8.2 Process policy

All of §4.4's `run_tool()` rules are mandatory. The three that bite hardest:

1. **`CREATE_NO_WINDOW` (0x08000000) plus `STARTUPINFO`/`SW_HIDE`.** Without them a GUI scan of 200
   genomes flashes 200 console windows over the UI.
2. **`stdin=subprocess.DEVNULL`.** In a `--windowed` PyInstaller build the parent has no valid std
   handles; leaving stdio at its defaults yields `OSError: [WinError 6] The handle is invalid` or a
   child that aborts at startup.
3. **Never combine `CREATE_NO_WINDOW` with `DETACHED_PROCESS` or `CREATE_NEW_CONSOLE`** —
   `ERROR_INVALID_PARAMETER`.

Also: `SetErrorMode(SEM_FAILCRITICALERRORS | SEM_NOGPFAULTERRORBOX)` in the parent, so a child
loader failure cannot pop a modal dialog behind the Tkinter window.

### 8.3 The BLAST+ payload

Archive `ncbi-blast-2.17.0+-x64-win64.tar.gz`, **143,400,333 bytes**, MD5
`dcd973097407a2910061ff4fb51b09fb` (the `.md5` file is exactly one line, two spaces between
fields). Pin `2.17.0/`, never `LATEST/`, so a silent NCBI bump cannot change typing results. The
`+` in the filename is a literal path character — if you build the URL with `urllib.parse.quote`,
pass `safe="/+"`, because `%2B` is a 404. HTTPS only; never the NSIS installer (it needs elevation
and writes `HKLM`).

**Extract only what is needed** (~35 MB of the ~440 MB expansion): `blastn.exe` (19,409,920 B),
`makeblastdb.exe` (14,923,264 B), `nghttp2.dll` (141,312 B — `blastn.exe` statically imports it;
forgetting it is a hard `STATUS_DLL_NOT_FOUND`), optionally `blastdbcmd.exe`, the matching
`*.exe.manifest` files, `LICENSE` and `BLAST_PRIVACY`. `ncbi-vdb-md.dll` is **not** needed.
Selective extraction is the single largest lever on first-run wall time with Defender on.

**The VC++ runtime is the #1 bootstrap failure.** PE import analysis shows `blastn.exe` needs
`MSVCP140.dll`, `VCRUNTIME140.dll` and `VCRUNTIME140_1.dll`, none of which are in the archive and
`MSVCP140.dll` is **not** guaranteed on a clean Windows 11. Mitigation ladder: (1) PyInstaller
already ships the two `VCRUNTIME140*.dll` via CPython; (2) app-local deployment of `MSVCP140.dll`
next to `blastn.exe` where the build machine's licence permits; (3) detect return code
`0xC0000135` (`STATUS_DLL_NOT_FOUND`) or `0xC0000142` (`STATUS_DLL_INIT_FAILED`) with empty output
and show the `https://aka.ms/vs/17/release/vc_redist.x64.exe` message. Never surface the raw
`WinError`.

Install root `%LOCALAPPDATA%\IOWA-Tech\WMLST\blast\` — per-user, no elevation, **not** OneDrive
Known-Folder-Move synced (so the index is never turned into a cloud placeholder, and no
`ERROR_SHARING_VIOLATION` from a sync lock), and excluded from roaming profiles. The
`.wmlst-install-ok` sentinel is written **last**, after `SHA256SUMS` verifies, so a half-extracted
tree from an AV quarantine is never trusted.

### 8.4 Text, encoding, newlines

| Stream | Policy |
| :-- | :-- |
| `mlst.fna` (written) | `encoding="utf-8", errors="replace", newline="\n"`; flush + `fsync` + **close** before launching `blastn` |
| source files (read) | decompressed byte stream decoded `utf-8`/`errors="replace"`, `utf-8-sig` when a BOM is present, universal newlines |
| `mlst.bls` (read) | `encoding="utf-8", errors="replace", newline=None`, plus `rstrip("\r\n")`. **Never `newline=""`** |
| CLI stdout/stderr | `reconfigure(encoding="utf-8", errors="replace")`, stdout additionally `newline="\n"` |
| `--outfile`, `--json`, `--novel`, `--html` | `newline="\n"`, UTF-8, no BOM |

`blastn -out` writes through the toolkit's text-mode stream, so rows are `\r\n`-terminated on
Windows. The last `-outfmt 6` field is `sstrand`, so a naive split yields `"plus\r"`, the
`== "minus"` test never fires, and `--novel` silently emits un-reverse-complemented sequences with
wrong MD5s. This is the highest-value single line of defence in the whole port.

Two verified BLAST facts that pin downstream behaviour: **`qseq` comes back UPPERCASE regardless of
query case** (so the novel MD5 is case-independent — hash it exactly as BLAST emits it, with no
`.upper()`/`.lower()`), and **`qseqid` is truncated at the first whitespace but `|` survives** (a
232-char pipe-separated defline yields `WGS_DEMO_DATABASE0000033|AAKJVO010000001|Salmonella`).
Do not "clean" pipes out of query ids.

### 8.5 Unicode and long paths

`blastn.exe`'s manifest is 406 bytes of `trustInfo` only — there is **no**
`<activeCodePage>UTF-8</activeCodePage>` — so it opens files through `CreateFileA` and cannot open
a path outside the system ANSI code page. `%LOCALAPPDATA%` contains the username, which is
frequently non-ASCII. The `\\?\` extended-length prefix does **not** help, because it is a wide-API
feature. The answer is `blastbin.ansi_safe()` (§4.4): ACP test → `GetShortPathNameW` → stage into
the ASCII temp root. 8.3 short-name generation can be disabled per volume, so detect
`short == long` and fall through. The frozen exe's manifest should also declare
`<ws2:longPathAware>true</ws2:longPathAware>` for Python's own file access.

### 8.6 `blastn` exit-code catalogue (verified against 2.17.0)

| Code | Meaning | WMLST action |
| --: | :-- | :-- |
| 0 | success (may be 0 hits) | parse `-out` |
| 0 + stderr `Warning: [blastn] Query is Empty!` | zero-byte query | treat as 0 hits ⇒ scheme `-`, `NONE` |
| 2 | `BLAST Database error: No alias or index file found …` | DB missing, or a space in `-db` (§5.5); actionable message naming the resolved path |
| **3** | `BLAST engine error: Warning: Sequence contains no data` | what `tests/data/empty.fa` produces. Surface the string **verbatim** (`test.sh:62-65` greps it), fail **that file only**, continue the batch |
| 1 | generic BLAST error | report stderr verbatim |
| `0xC0000135` / `0xC0000142` | DLL missing / init failed | the VC++ redist message (§8.3) |
| `0xC0000005` | access violation — almost always a truncated/quarantined index | re-verify `SHA256SUMS`, offer re-extract |
| `None` after `TimeoutExpired` | hung child | `kill()` **then** `wait()` |

Default per-file timeout **900 s** (`--blast-timeout`). Reference timings against the 162-scheme DB:
`example.fna` (2.5 MB, 42 contigs) **2.4 s**; `issue146.fa` (5 MB, 1 contig) **5.0 s**. 900 s is
~180× headroom.

### 8.7 Filesystem and antivirus

NTFS is case-insensitive/case-preserving. Audited across all 162 schemes and 1,432 files: all
directory names are lowercase; no case-insensitive collisions among directories, among files within
a directory, or among `scheme.locus` prefixes; no reserved DOS device names; no characters illegal
on NTFS. **Two filenames contain an apostrophe** (`halobacteria/rpoB'.tfa`, `mhominis_3/p120'.tfa`)
— legal on NTFS, harmless with argv lists, and a quoting minefield with a `cmd.exe` string. Scheme
lookup is **case-sensitive**: `--scheme SAUREUS` is an error, and path existence is never a
validator.

Defender: the first-run scan storm is mitigated primarily by selective extraction (§8.3); the first
search after install touches every mapped page of `.nsq`/`.nin`/`.nhr` and can take several times
longer than steady state, so the GUI shows *"Preparing database (first run may take a minute)…"*.
Ship `scripts/Add-DefenderExclusion.ps1` (`Add-MpPreference -ExclusionPath
"$env:LOCALAPPDATA\IOWA-Tech\WMLST"`) and **offer** it under Help → Troubleshooting; never invoke it
silently and never request elevation. Warn — do not block — when `--datadir`/`--blastdb` points
under a OneDrive root or a UNC path (Files-On-Demand turns `.nsq` into a placeholder and `blastn`'s
mmap triggers a synchronous cloud fetch mid-search). If an output write fails with `WinError 5`,
name Controlled Folder Access as the likely cause.

### 8.8 The prebuilt index is portable — evidence

1. `mlst.fa.njs` reports `"db-version": 5` and `"dbname": "mlst.fa"` (relative, not absolute).
2. NCBI itself distributes one platform-neutral copy of every BLAST DB, with no per-OS variants.
3. Grepping all 12 index files for the build directory returns **zero** hits.
4. Relocation test: the 12 `.n*` files copied to a different directory (one containing a space),
   without `mlst.fa`, produced byte-identical output.
5. `.ndb`/`.ntf` are LMDB with little-endian magic `0xBEEFC0DE` and a 4096-byte page size;
   `.nos`/`.not`/`.nto` begin with a little-endian record count. Windows x64 and Linux x64 are both
   little-endian with 4 KiB pages.

**Conclusion:** BLAST v5 databases are portable across little-endian 64-bit platforms. Ship the 12
prebuilt `.n*` files in release artifacts; do **not** ship `mlst.fa` (saves 113 MB); do not run
`makeblastdb` on the user's machine for the bundled DB. The index is **not** byte-reproducible
(`makeblastdb` embeds a timestamp), so compute `db/blast/SHA256SUMS` at **packaging time** from the
artifacts actually shipped and verify it on first run and on `--check`. Keep `makeblastdb.exe`
bundled anyway — the updater and the custom-scheme workflow need it.

## 9. CONCURRENCY

* `--threads` maps to `blastn -num_threads`. Default **1** (C3). Clamp to
  `[1, min(os.cpu_count() or 1, 64)]`; 64 is the Windows processor-group boundary and `blastn` does
  not span groups. `--threads 0` means auto.
* **Verified: thread count does not change output bytes.** `example.fna` produced MD5
  `fc218231a3a46a696c51cbd96c22d3ff` at 1/2/4/8/16 threads and at `-mt_mode 1` and `2`; row order
  as well as row content was preserved. `--threads` is a pure performance knob. **Never pass
  `-mt_mode`.**
* Threads do nothing for a single-contig query (BLAST splits by query at the default `mt_mode 0`):
  measured 5.56 s / 5.08 s / 6.39 s / 5.51 s at 1/2/4/8 threads on `issue146.fa`. The GUI tooltip
  must say so.
* **The real win is file-level parallelism**: `concurrent.futures.ThreadPoolExecutor` of width
  `cfg.jobs` (not `ProcessPoolExecutor` — the work is in the child process, and threads avoid
  Windows `spawn` and the PyInstaller re-exec problem). `jobs * threads <= cpu_count`. Peak RSS is
  ~270 MB per concurrent `blastn`; refuse more workers than `available_RAM / 400 MB`.
* **Every worker gets its own job directory.** Sharing `mlst.fna`/`mlst.bls` is the classic port bug.
* Results are collected out of order and **re-sorted into argv order** before `RunResult` is built.
* GUI: all launches happen on worker threads; results reach the Tk main thread through one
  `queue.Queue` drained by a single `root.after()` chain. **Never touch a Tk widget from a worker
  thread** — Tcl is not thread-safe and on Windows this surfaces as random
  `RuntimeError: main thread is not in main loop` or a silent hang.
* Cancel keeps `Popen` handles in a registry; `terminate()` → `wait(5)` → `kill()` → `wait()`. On
  Windows `terminate()` *is* `TerminateProcess`, so a cancelled `blastn` leaves a partial
  `mlst.bls` — which step 23's delete-before-run already neutralises.

## 10. THE GUI (`gui.py`)

**The GUI never computes anything.** It renders what `engine` returns and MUST NOT re-derive ST,
STATUS, SCORE or any allele code. Enforced by `tests/test_layering.py`, which greps `gui.py` for
`subprocess`, `Popen`, `blastn`, `makeblastdb` and for any re-implementation of `status_column`.

### 10.1 Shape

Single `tk.Tk` root, one `ttk.Notebook` with three tabs — **Analyse**, **Database**, **Settings** —
a status line and a footer. Default geometry `1180x760`, minimum `960x640`, geometry and zoom state
persisted and restored only when the saved rectangle lands on a visible monitor.

**DPI awareness MUST be set before `tk.Tk()` is constructed**: try
`SetProcessDpiAwarenessContext(-4)` (per-monitor v2), then `SetProcessDpiAwareness(2)`, then `(1)`,
then `SetProcessDPIAware()`. After construction, `root.tk.call("tk", "scaling",
root.winfo_fpixels("1i") / 72.0)`. Every hard-coded **pixel** value goes through
`px(n) = int(round(n * SC))` where `SC = dpi / 96.0`; every **font size** is given in points and is
**not** multiplied by `SC` (Tk's scaling already handles it). Double-scaled fonts are the classic
HiDPI bug — `tests/test_gui_headless.py` asserts `px(16) == 24` at 144 dpi and that no font size
was scaled twice.

Theme: `style.theme_use("clam")` on **all** platforms — `vista`/`xpnative` refuse background
colouring, and `clam` is the only stdlib theme that honours `configure`/`map` fully. Cards are a
1 px bordered frame wrapping a surface frame; there is no ttk border radius and rounded corners
must not be faked with images (they break at 150 % DPI). Spacing scale: 4/8/12/16/24/32 × SC.
If `SystemParametersInfoW(SPI_GETHIGHCONTRAST)` reports high contrast, fall back to the system
palette rather than the custom hex palette.

### 10.2 Analyse tab

State machine `IDLE → RUNNING → RESULTS`, with `CANCELLED` and `ERROR` re-entering `RESULTS`
(partial results are kept and remain exportable). New drops in `RESULTS` append rows.

* **DropZone** is a `tk.Canvas` (not a Frame) so the dashed border can be redrawn on `<Configure>`.
  Idle / hover / drag-over / keyboard-focus states differ in outline colour, width and fill; the
  drag-over headline swaps to *"Release to analyse"*. The glyph is drawn with `create_line`/
  `create_polygon` — **no emoji, no bitmap**. Click anywhere browses; `Return`/`space` browses
  files, `Shift-Return` browses a folder.
* **Drag-and-drop is optional** (C21). `tkinterdnd2` is imported in a `try/except`; the Tcl file
  list MUST be split with `widget.tk.splitlist(event.data)`, never `str.split()`, because paths
  with spaces arrive brace-wrapped. Without it the headline becomes *"Click to choose your FASTA
  file"* and one status-line note appears per session. No dialog, no traceback.
* A dropped `.txt` is offered as a **fofn** with a three-way confirm.
* A folder drop scans recursively to depth 3 and confirms above 50 files with a time estimate.
* **Progress is honest.** The overall bar is determinate with
  `value = done*100 + current_file_percent`, driven by the engine's `ProgressEvent` and the phase
  weights of §5.16. During the BLAST phase the overall bar holds and a thin **indeterminate** bar
  proves liveness. There is no fake timer anywhere.
* **Results tree**: `ttk.Treeview(columns=("scheme","st","status","score"), show="tree headings")`
  with `#0` carrying FILE. Heading words are identical to `bin/mlst:151`. Child rows (per-locus)
  are inserted lazily on `<<TreeviewOpen>>`, reuse the four data columns, and are preceded by a
  muted caption row so reused columns are never ambiguous. Status cells render `"● PERFECT"` —
  **colour is never the only channel**. Sorting is stable with the original order as the secondary
  key; child rows are never re-sorted (locus order is scheme gene order). Above 2,000 rows, insert
  in chunks of 200 from the pump.
* Single-file mode additionally shows a summary card with the ST at ~28 pt. When `st == "-"` it
  renders the words **`not assigned`**, never a bare hyphen at display size.
* Action buttons (`Open HTML report`, `Save TSV…`, `Save JSON…`, `Save novel alleles…`,
  `Copy row`, `Clear`) all delegate to `report.py`. **The GUI never formats a compat output
  itself**, and every file write runs on the worker thread so a slow network share cannot freeze
  the UI.

### 10.3 Database tab

Columns map 1:1 onto `--info`, with two presentation changes that exist only in the GUI: `LOCII` is
spelled **`LOCI`** (the CLI keeps the upstream misspelling), and `Unknown` renders as a muted `—`.
A `SPECIES` column is added from `scheme_species_map.tab`. Counts come from `<scheme>_info.json`
(fast path) and are computed from `<scheme>.txt` lazily, on the worker thread, showing `…`
meanwhile. **Loading 162 schemes must never block startup**: the tab populates on first activation.

The update flow is: *Check for updates* → a per-scheme plan dialog with checkboxes, byte estimate
and a "keep a backup" option → *Update now* → two-level progress → atomic swap → catalogue reload
and footer refresh, **no restart**. Updating is blocked while an analysis runs (button disabled,
tooltip explains). Cancel is live and honoured between scheme commits. Offline/DNS failures produce
the friendly dialog, never a traceback.

### 10.4 Settings tab

Defaults MUST equal the reference defaults: minid **95**, mincov **50**, minscore **50**, exclude
set exactly `ecoli, abaumannii, vcholerae_2, senterica_achtman_2`. "Restore reference defaults"
restores those and status-lines the fact. Selecting *"Always use this scheme"* greys out the
minimum-score control, displays `0`, and shows the ⚠ line mirroring `bin/mlst:91-94`. Validation is
`validatecommand` + a `<FocusOut>` clamp; a clamped field flashes and the status line explains.
Changing a setting while results are on screen shows a dismissible inline bar with
`[Re-run all files]` (F5). Settings are written debounced 800 ms, atomically; a corrupt file is
renamed `settings.bad.json` and defaults are used with one status-line note.

### 10.5 Threading

Exactly the `AnalysisController` contract of §4.10 and §9. Testable invariants:

1. `assert_main_thread()` guards `view.dispatch`, the status line setter, every tree mutation and
   every dialog constructor.
2. The worker never imports `tkinter`.
3. `Msg` carries only plain data and engine dataclasses — never a widget reference.
4. `daemon=True`; `WM_DELETE_WINDOW` sets cancel, joins ≤ 1,500 ms, then destroys regardless.
5. Exactly one `after()` chain; the elapsed label and the indeterminate bar ride on it.
6. A second `start()` while a worker lives is impossible; files dropped during a run are queued.

### 10.6 Friendly errors — never a stack trace

`root.report_callback_exception` is routed to the error dialog, so nothing reaches the console.
Each dialog has a headline, a body, a short "what to try" list, and a **collapsed**
`▸ Show technical details` fold containing the traceback plus an environment block (WMLST version,
Python, OS build, BLAST path/version, DB date) and a `[Copy details]` button. Mapping:

| Exception | Headline | Body |
| :-- | :-- | :-- |
| `EmptyInputError` | We couldn't read that file | `{name}` doesn't contain any DNA sequence. |
| `UnsupportedFormatError` | That file format isn't supported | `{name}` isn't FASTA, GenBank or EMBL. |
| `BlastNotFoundError` | WMLST needs its search engine | → routes to the bootstrap modal, **not** the error dialog |
| `BlastFailedError` | The search engine stopped unexpectedly | exit code + last 3 stderr lines under the fold |
| `DatabaseMissingError` | The MLST database is missing | expected at `{path}` |
| `DatabaseCorruptError` | The MLST database looks damaged | offers `[Rebuild search index]` |
| `OutOfDiskError` | Not enough free space | `{needed}` needed on `{drive}`, `{free}` free |
| `PermissionError` | Windows wouldn't let us write there | names Controlled Folder Access |
| anything else | Something went wrong | `str(exc)` one-liner + fold |

During a **batch**, a failed file produces **no dialog** — the row turns red and the status line
says `1 file failed (click the red row for details)`. For a single-file run the dialog opens
immediately. Everything is also appended to `%LOCALAPPDATA%\WMLST\logs\wmlst-YYYYMMDD.log`
(rotating, 5 × 1 MB), viewable from Help → Show log.

### 10.7 First run without BLAST+

A modal, shown once at first launch and again as a gate the first time a file is dropped without
BLAST present. Copy must say **"about 137 MB to download, about 35 MB installed"** (C11) and must
name the install path and state that no administrator rights are needed. Buttons: `Download now`
(default) / `Not now`, plus a `▸ I already have BLAST+ installed` fold with a path picker validated
by `blastn -version`. During the download the button becomes `Cancel`; cancelling deletes the
partial file. On success the modal closes, the footer updates, and **any file the user already
dropped starts analysing automatically**. `Not now` leaves the app in a degraded state with an
inline `⚠ Search engine not installed — [Install now]` banner. Failure shows the friendly dialog
with a copyable manual-installation block. **No splash screen** — a splash on a 1.5 s startup is
exactly the 1998 smell being avoided.

### 10.8 Accessibility (normative)

Every interactive widget is focusable with a visible 3 px focus ring (the Canvas dropzone and the
Treeview draw their own, since `clam` will not). Tab order is documented and tested by walking
`tk_focusNext`. Minimum hit target 32 × 32 px at 100 % DPI. Colour is never the sole channel.
The status line is a live region and never a `messagebox`; transient messages auto-revert after
6 s. Only six things in the entire application are modal: the BLAST bootstrap, the update
confirmation, the error dialog, About, the unsaved-results confirm, and the >50-files confirm.

### 10.9 Startup order

```
dpi_fix()  →  root = make_root()  →  apply_scaling + install_theme  →  root.withdraw()
→  Prefs.load()  →  build widgets (NO disk scan, NO blast probe)
→  deiconify + update_idletasks          # first paint < 400 ms
→  after(50, post_start)                 # worker job: locate blast, read VERSION.txt, catalogue
→  mainloop()
```
Nothing blocking happens before `mainloop()`. Footer fully populated within 1.5 s.

## 11. THE HTML REPORT (`report.py`)

### 11.1 Non-negotiables

1. **Self-contained.** Zero references to any external origin. A CI test greps the rendered output
   for `http://`, `https://`, `//cdn`, `<link rel="stylesheet"`, `src=` on `<script>`, `@import`,
   and `url(` with a non-`data:` scheme, and fails on any hit. The only permitted non-inline URI is
   the `data:image/svg+xml;base64,…` vendor mark.
2. **No templating engine.** No `jinja2`, no `markupsafe`. Assembly is f-strings / `io.StringIO`
   over `h()` / `attr()` / `js_json()`.
3. **Escaping is not optional.** `qseqid`, `label` and `filename` are attacker-controlled in the
   realistic sense — a FASTA arrives from a sequencing provider, the report opens from `file://`
   with a full local origin, and it gets emailed onward. A contig named
   `><script>fetch('file:///C:/…')</script>` MUST render as inert text.
4. **No `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`, `eval`, `new Function`,
   string-`setTimeout`, `fetch`, `XMLHttpRequest`, `WebSocket`, `import(`, or any inline `on*=`
   handler.** Grepped in CI.
5. **No CSS injection.** No user string ever reaches a `<style>` block or a `style=` attribute.
   Status colours come from a whitelisted class map; an unknown status falls back to `s-unknown`
   with the raw string rendered as escaped text.
6. DNA is validated before inlining: `re.fullmatch(r"[ACGTRYSWKMBDHVNacgtryswkmbdhvn-]*", seq)`,
   else a red notice replaces the sequence.
7. A meta CSP (`default-src 'none'; style-src 'unsafe-inline'; script-src 'unsafe-inline';
   img-src data:; …`) and `<meta name="referrer" content="no-referrer">` are emitted as a **second**
   lock. Escaping is the first; `file://` UAs honour CSP inconsistently.
8. `translate="no"` on contig ids and sequence blocks so page translation cannot mangle identifiers.
9. Atomic write (`path + ".tmp"` then `os.replace`), UTF-8, `newline="\n"`, no BOM.
10. Deterministic: two renders with a frozen clock are byte-identical. Anchors are
    `sample-{1-based index}`, never derived from user data.

### 11.2 Structure

`masthead` (branding + title + theme toggle) → `run-meta` `<dl>` → `batch` summary (only when
`n > 1`) → one `article.card` per sample in **argv order, never re-sorted** → global novel section
→ legend → method paragraph → colophon → JSON island → one `<script>`.

The **run-meta block always prints `minid`, `mincov`, `minscore`, `threads`, `exclude` and `scheme`
(or `auto-detect`) even at their defaults** — a report is a record, and "what settings produced
this" must not depend on what the operator happened to type. Non-default values get a `†` marker.
When `--scheme` is set, the threshold note shows the **effective** `minscore` of 0 (B11).

Per-sample card: filename, the big ST, the scheme, the species line (with the mandatory
"not an independent identification" caveat), the status badge, the score meter, a stats line, the
locus table, the runner-up `<details>`, and the novel-allele `<details>`.

### 11.3 The seven status badges

Each badge carries a **glyph AND the uppercase word AND a colour AND a `data-status` attribute**,
and the card's left border differs in **style** as well as colour (`solid` for PERFECT/NOVEL/OK,
`double` for MIXED, `dashed` for MISSING/NONE, thick `solid` for BAD). A monochrome print or a
deuteranope reader loses nothing. The glyph is `aria-hidden` so a screen reader hears the word once.

| STATUS | Glyph | Class | User-facing sentence (verbatim) |
| :-- | :-- | :-- | :-- |
| PERFECT | ✔ | `s-perfect` | Every locus matched a known allele exactly, and the combination is a recognised sequence type. |
| NOVEL | ✚ | `s-novel` | Every locus matched a known allele exactly, but this combination is not yet a named sequence type — it may be a new ST worth submitting to PubMLST. |
| MIXED | ⧉ | `s-mixed` | At least one locus matched two or more different alleles equally well. This usually means the assembly contains more than one strain, or a duplicated gene — check culture purity before reporting. |
| MISSING | ◌ | `s-missing` | At least one locus could not be found in this assembly. It may be incomplete, or the locus may genuinely be absent — an ST cannot be assigned. |
| BAD | ⚠ | `s-bad` | The best-matching scheme scored below 70 out of 100. Treat this result as unreliable: wrong organism, heavily fragmented, or contaminated. |
| OK | ● | `s-ok` | The scheme matched reasonably well, but at least one locus is only an approximate or partial match, so no exact sequence type could be assigned. |
| NONE | ○ | `s-none` | No MLST scheme matched this file at all. Check that it really contains assembled contigs for a species covered by one of the 162 bundled schemes. |

### 11.4 Locus table and evidence columns

A real `<table>` with `<caption>`, `<th scope="col">` and the locus cell as `<th scope="row">` —
never a div grid, never `role="table"`. The `code` string is rendered **verbatim** (escaped); the
report classifies but never rewrites. Legend entries for `16`, `~16`, `16?`, `-`, `1,2`, `0` are
always rendered and never collapsed.

| Column | Computation | `<th title>` |
| :-- | :-- | :-- |
| Contig | `qseqid`, full header in `title` | BLAST `qseqid` |
| Position | `min(qstart,qend)`–`max(qstart,qend)`, thousands separators, en-dash | `qstart`/`qend`, 1-based inclusive |
| Strand | `plus` → `+ forward`, `minus` → `− reverse`, with the word in `.visually-hidden` | `sstrand` |
| Identity | `100*nident/length`, 1 dp | `nident / length` |
| Aligned / allele | `length` / `slen` bp | alignment vs allele length |
| Coverage | `100*nident/slen`, 1 dp | **the quantity `--mincov` is applied to** |

Do **not** display BLAST's own `pident` (`mlst` never reads it) and do **not** define coverage as
`length/slen` — a user who checks the arithmetic against `--mincov` must find that it adds up. A
footnote states the definition. For `novel`/`partial` calls the percentage formatter floors to 1 dp
(`math.floor(v*10)/10`) so an inexact match can never print `100.0 %` (C14); exact calls print
`100.0 %` unconditionally. A comma code renders one evidence row per component, in the
numerically-sorted order of step 51, with `rowspan` on the locus and call cells.

Runner-up table: every scored scheme including below-threshold ones (muted, pilled
`below --minscore 50`), with a final muted line naming the schemes dropped by `--exclude` (B10).
**A tie is surfaced loudly, in the card body and not inside a fold**, because it is a clinically
meaningful ambiguity:
`⚠ Tie: sepidermidis also scored 100. WMLST reports the alphabetically first scheme. Confirm the
species by another method before using this ST.`

Novel alleles: header line byte-identical to what `--novel` writes, sequence wrapped at 60 columns
inside `<pre>`, and a **mandatory** note that a minus-strand capture is shown already
reverse-complemented (otherwise the coordinates in the locus table look like a bug). Sequences over
`--html-max-novel-bp` show a length notice instead. When `--novel` was not given, one muted line
tells the user how to get the sequences.

Batch section (n > 1): status chips, a client-side filter and sort (default order is **input
order**, with a `Reset order` button), and an ST frequency roll-up grouped by `(scheme, st)` with
`st == "-"` kept separate per scheme. The roll-up carries the mandatory line:
*"Samples sharing a scheme and sequence type carry the same alleles. That is consistent with a
common source, but MLST alone does not prove an outbreak link."*

### 11.5 `CSS_TEXT`

One `<style>` block, tokens on `:root` for light, overridden under
`@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) {...} }` **and** under
`:root[data-theme="dark"]` so the explicit toggle wins in both directions. No colour may have its
only definition inside a media or `[data-theme]` block. `body` gets an explicit token background.

Required blocks: reset/base; masthead; run-meta; cards with per-status left borders; badges; score
meter (with a hatched fill for the low bands so the band survives greyscale printing); tables with
sticky headers inside `.table-wrap { overflow-x: auto }`; `details`; batch chips/filters; legend;
novel; empty state; colophon; responsive breakpoints at 760 px and 420 px (usable to 320 px, with
only `.table-wrap` scrolling horizontally); `@media (prefers-reduced-motion: reduce)`;
`@media (prefers-contrast: more)`; `@media (forced-colors: active)` (this is a Windows product);
and `@page { size: A4 portrait; margin: 14mm 12mm 16mm }` with a print block that forces the light
palette, hides `.no-print`, sets `break-inside: avoid` on cards and rows, repeats `<thead>` across
pages, and **prints every `<details>` expanded** — a printed report must not hide evidence.

**Contrast is a checked-in contract.** `tests/test_report_static.py` recomputes the WCAG ratio for
every declared `(fg, bg)` pair from the CSS tokens and asserts ≥ 4.5:1 (≥ 3.0 for ≥ 14 pt bold), so
a palette edit that breaks AA fails the build. The shipped palette measures ≥ 6.2:1 on every badge
pair in both themes. `tinycss2` must parse `CSS_TEXT` with zero errors.

### 11.6 `JS_TEXT`

≤ 120 lines, IIFE, `'use strict'`, no dependencies, **progressive enhancement only** — the report
is complete and readable with JavaScript disabled or stripped by a mail client. Five features:
theme toggle (persisted via `localStorage` inside `try/catch`, since a `file://` origin can throw);
expand/collapse all `<details>`; batch text + status filter driven by a server-side-built,
pre-lowercased `data-search` attribute, updating a `role="status"` live count; stable numeric-aware
column sort maintaining `aria-sort`; and copy buttons using `navigator.clipboard.writeText` with an
`execCommand('copy')` fallback and a `role="status"` confirmation. Copy buttons are `.no-print` and
are not rendered at all when their target section is absent.

## 12. TEXT OUTPUT FORMATS — the byte-identity surfaces

### 12.1 `print_row` and the quoting rule (`bin/mlst:417-428`)

```python
def print_row(cols, sep, out):
    fields = []
    for c in cols:
        c = str(c)
        if '"' in c or sep in c:      # 1. quote ONLY on a quote char or the CURRENT separator
            c = c.replace('"', '""')  # 2. double quotes
            c = c.replace("\\", "\\\\")  # 3. THEN double backslashes  (non-standard; keep it)
            c = '"' + c + '"'         # 4. wrap
        fields.append(c)
    out.write(sep.join(fields) + "\n")   # 5. LF, never CRLF
```

Quirks that MUST survive: a field containing a **comma** is NOT quoted in TSV mode, and a field
containing a **tab** is NOT quoted in CSV mode (the trigger is the *current* `$OUTSEP`). Backslash
doubling happens only inside quoted fields and only **after** quote doubling, so `a"b\c` becomes
`"a""b\\c"`. Newlines in a field do not trigger quoting. **Do not use the `csv` module** — it
cannot reproduce this. Pinned by `test.sh:127-130`: `mlst --csv mixed.fa.zip` line 0 contains
`,"MLST_gyrB(1,1)",`.

### 12.2 Header rows (`bin/mlst:146-152`)

* `--scheme X --legacy` ⇒ `print_row("FILE", "SCHEME", "ST", *genes)`. This wins over `--full`
  (it is an `elsif`, and the row printer checks legacy first).
* `--full` ⇒ `print_row("FILE", "SCHEME", "ST", "STATUS", "SCORE", "ALLELES")`.
* Default mode ⇒ **no header at all**.
* With `--outfile`, the header goes to the file (it is opened before the header is emitted) and
  **stdout stays empty** (`test.sh:158-165` asserts empty stdout and exactly 2 lines in the file).

### 12.3 Row layouts (`bin/mlst:186-208`)

| Mode | Row |
| :-- | :-- |
| legacy | `LABEL  SCHEME  ST  code1 … codeN` — bare codes, one column per locus. With nothing found: `LABEL  X  -  -  …  -` with `len(genes)` hyphens from the sentinel |
| full | `LABEL  SCHEME  ST  STATUS  SCORE  gene1(code1);gene2(code2);…` — `;`-joined, **no spaces** |
| default | `LABEL  SCHEME  ST  gene1(code1)  gene2(code2)  …` — one column per locus |

When `scheme == "-"`: default mode emits exactly **three** fields (`LABEL  -  -`), and `--full`
emits an **empty** ALLELES field, producing a trailing separator
(`none.fa\t-\t-\tNONE\t0\t\n`). Do **not** substitute `-`. `SCORE` is written `str(int(score))` —
no padding, no decimal point.

### 12.4 JSON (`bin/mlst:210-228`)

```python
json.dumps(obj, indent=3, separators=(",", " : "), ensure_ascii=True)   # NO trailing newline
```
Top level is an **array**, one object per input file, in argv order. Exactly five keys, in this
order: `id` (= LABEL, honours `--label`/`--nopath`), `filename` (= the raw argv path), `scheme`,
`sequence_type`, `alleles`. `alleles` is JSON **`null`** when `scheme == "-"`, otherwise an object
mapping gene → the **post-duplicate-sort code string** in scheme gene order. **Every value is a
string**, including `sequence_type` and every allele — `"184"`, never `184`. Emitting a number is a
byte-compat failure. Written once, after all inputs; a run that dies mid-way writes no JSON.
Key ordering is fixed by WMLST (D2) because upstream's is a randomised Perl hash.

### 12.5 `--list` / `--longlist` / `--info` (`bin/mlst:96-119`)

* `--list`: `" ".join(catalog.names()) + "\n"` to **stdout** — not `$OUTFH`, not `print_row`.
* `--longlist`: one `print_row(name, *genes)` per scheme, sorted (D1).
* `--info`: header `print_row("SCHEME","LOCII","TYPES","ALLELES","DATE","LOCII_NAMES")` — **six**
  columns; the `,,` at `bin/mlst:112` is a Perl no-op — then one row per scheme sorted by name:
  `print_row(name, num_genes, num_genotypes, num_alleles, last_updated, " ".join(genes))`.
  `DATE` is `Unknown` for all 162 shipped schemes (C12).
* All three exit 0 immediately, **before** the empty-argv check.

### 12.6 Novel FASTA (`bin/mlst:230-250`)

`>{scheme}.{locus}-{md5hex} {LABEL}\n{seq}\n` — one unwrapped sequence line, description is the
**label**, not the path. Deduplicated by the full id across all input files, first occurrence wins.
An empty file is still created when there are no novel alleles. `msg("Found", n, "novel alleles")`.

### 12.7 WMLST-only outputs

`--html`, `--tsv-evidence` and the GUI's exports are supersets. They MUST NEVER alter, reorder or
reformat a compat output. `--html` writes only when asked; the "Wrote HTML report: <path>" notice
goes to stderr even under `--quiet` (it is an output-location notice, not a witticism).

## 13. PACKAGING, LICENSING, TESTING

### 13.1 Packaging decisions

* **Zero mandatory third-party runtime dependencies.** `[project] dependencies` is empty and stays
  empty; `scripts/check_stdlib_only.py` walks `wmlst/` with `ast` and asserts every top-level
  import is in `sys.stdlib_module_names` or starts with `wmlst`, with the single structural
  exception of a `try/except ImportError`-guarded `tkinterdnd2`. This is a **licensing**
  simplification as much as a packaging one (§13.3).
* Extras: `gui` (tkinterdnd2), `build` (pyinstaller, pillow), `test`, `lint`, `dev`.
* Five entry points: `wmlst` (console), **`wmlst-gui` in `[project.gui-scripts]`** so setuptools
  emits a `pythonw`-bound exe and no console flashes, `wmlst-update-db`, `wmlst-make-blast-db`,
  `wmlst-show-seqs` (the last is required by bats case 40).
* The DB reaches the wheel via `[tool.setuptools.package-dir] wmlst_db = "db"` plus
  `package-data`; `data_files` would install to `sys.prefix`, which is wrong under a frozen
  bundle. `db/__init__.py` and `db/pubmlst/__init__.py` are committed 3-line files.
  Resulting wheel ≈ **6.3 MB** — far under PyPI's limit, so no external DB download is needed.
* **PyInstaller one-folder, never one-file.** One-file would unpack 1,108 DB files into `%TEMP%`
  on every launch (20–60 s), would not give the bootstrapped BLAST binaries a stable path, and
  would not persist the derived index. Two exes are built — `WMLST.exe` (`console=False`) and
  `wmlst-cli.exe` (`console=True`) — and **`MERGE()` is mandatory** so the 116 MB database is
  stored once in `_internal/` rather than twice. `upx=False` (UPX corrupts MSVC runtime DLLs and
  trips AV heuristics). `excludes` strips numpy/scipy/pandas/matplotlib/**PIL**/pytest/setuptools.
* A `runtime_hook_noconsole.py` installs `io.StringIO` substitutes when `sys.stdout`/`stderr`/
  `stdin` are `None` under `--windowed`, and sets `PYTHONIOENCODING=utf-8` / `PYTHONUTF8=1`.
* `multiprocessing.freeze_support()` is the first statement of both `main()` functions.
* Inno Setup 6, `Compression=lzma2/max`, `SolidCompression=yes`, `ArchitecturesAllowed=x64compatible`,
  `MinVersion=10.0.17763`, `PrivilegesRequired=lowest`. Installer ≈ 28 MB; portable zip ≈ 30 MB
  (the DB compresses ~20:1, measured: 5.8 MB DEFLATE / 6.0 MB tar.gz / 6.13 MB zip).
  `LICENSE.txt` and `NOTICE.txt` are installed into `{app}` — a GPL §1 requirement installer
  authors routinely forget. `[UninstallDelete]` removes only derived data, never user results.
* **Not code-signed.** README, `docs/WINDOWS.md` and every Release body must state plainly that
  SmartScreen will show *"Windows protected your PC"*, that this is a reputation signal and not a
  virus warning, that the fix is **More info → Run anyway**, and that `SHA256SUMS.txt` plus the
  public CI build log are the provenance record. Do not claim unsigned code is "safe", do not
  suggest registry tweaks, and do not suggest a self-signed certificate (SmartScreen ignores
  untrusted roots).

### 13.2 Repository hygiene

`db/pubmlst/` is **committed on purpose** (116 MB raw ⇒ ~5.8 MB of git objects) and must never be
gitignored, LFS-ed or archived; `tests/test_packaging.py::test_db_is_tracked` fails the build if it
is. `db/blast/` is gitignored. `.gitattributes` is load-bearing: `core.autocrlf=true` on a
contributor's machine would rewrite `.tfa` line endings and **change every allele's MD5 and every
BLAST hit**, so `db/pubmlst/**`, `db/scheme_species_map.tab`, `tests/data/**` and `tests/golden/**`
are all marked `-text`, and `*.tfa`/`*.ico`/`*.png`/`*.gz`/`*.bz2`/`*.zip` are `binary`.

### 13.3 Licence

Upstream `ref-mlst/LICENSE` is the **GNU GPL version 2, June 1991** with **no** "or any later
version" clause. A port is a translation and therefore unambiguously a derivative work under GPLv2
§0. **WMLST is `GPL-2.0-only` and cannot be anything else** — not GPLv3, not MIT, not "GPLv2 for
the ported parts and MIT for the new ones" (§2(b) licenses the derivative as a whole). Consequences:

* `LICENSE` is the GPLv2 text, byte-identical to upstream's.
* SPDX `GPL-2.0-only` used consistently in `pyproject.toml`, the trove classifier, `CITATION.cff`
  and the Inno `LicenseFile`.
* Every `.py` carries an SPDX header naming both copyrights; direct line-by-line translations
  (`engine.py`, `schemes.py`, the BLAST-DB builder) additionally name the upstream file and line
  range. `scripts/check_headers.py` enforces presence in CI.
* `NOTICE` records the derivation, the PubMLST data provenance and citation, the non-bundled NCBI
  BLAST+, and the source-code offer.
* Publishing every release from a public tagged repository with the CI build log referenced
  satisfies §3(a)/(b).
* **A GPLv2 program cannot link an Apache-2.0 library** (the patent-termination clause is
  GPLv2-incompatible). This is why §13.1's zero-dependency rule is a hard rule and why any new
  dependency needs a licence review. `tkinterdnd2` (MIT) and PyInstaller (GPLv2 with the bootloader
  exception, build-time only) are clean.
* **Attribution is mandatory and must credit upstream first.** The README's ATTRIBUTION section,
  the GUI About box, the HTML report colophon and the CLI banner all name **Torsten Seemann** and
  the PubMLST citation (Jolley, Bray & Maiden 2018, *Wellcome Open Res* 3:124, PMID 30345391)

## 15. THE COMPLETE DIVERGENCE REGISTER

Every intentional difference from upstream. **None of them changes a numeric result** except D11,
which is off by default and loudly labelled.

| # | Divergence | Justification |
| :-- | :-- | :-- |
| D1 | Deterministic ordering everywhere (`sorted()` for scheme directories, candidate insertion, stable score sort, tie-break by scheme name) | upstream randomises hash iteration per process; ties are decided by a coin flip. Affects only exact ties, which upstream cannot reproduce run-to-run |
| D2 | JSON key order fixed to `id, filename, scheme, sequence_type, alleles`, alleles in gene order | upstream's order is a randomised Perl hash |
